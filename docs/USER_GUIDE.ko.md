# Retulo 사용 안내

파일을 만드는 실제 작업을 일정한 공간에서 시작하고, 같은 작업을 다른 대화에서 이어갈 수 있게 관리합니다. 설치 후 Codex의 기본 작업 절차로 적용됩니다. 사용자가 엔진 이름이나 명령을 기억할 필요는 없습니다.

## 처음 작업할 때

평소처럼 결과물을 요청하면 됩니다.

> 제품 소개 제안서를 Markdown 파일로 작성해줘. 원본은 보존해줘.

> 이 프로젝트의 합계 계산 오류를 고치고 기존 테스트로 확인해줘.

에이전트는 파일을 쓰기 전에 작업을 시작하고, 엔진이 반환한 경로에 결과물을 저장합니다. 기본 위치는 `~/Documents/RetuloWorkspaces`이며 엔진 소스 저장소와 분리됩니다. 질문이나 계획만 요청하면 작업공간을 만들지 않습니다. 전역 지침과 세션·요청 훅이 기본 절차를 제공하고 현재 모델이 작업 의도를 판단합니다. 엔진은 모든 호스트 도구를 가로채는 보안 장치가 아닙니다.

짧은 작업은 결과물과 `.workspace/task.json`으로 시작합니다. 길어지면 같은 폴더에 `WORKSPACE.md`와 필요한 자료 폴더를 추가합니다. JSON이 상태의 기준이고 Markdown은 현재 상태를 읽기 쉽게 보여주는 안내서입니다.

## 이어서 작업할 때

> 이 안내문에 문의처를 추가해서 새 버전으로 저장해줘. 이전 파일도 보관해줘.

같은 대화나 해당 작업 폴더에서는 기존 연결 정보를 확인합니다. 새 대화에서는 기존 파일 또는 작업 폴더를 알려주면 됩니다. 작업 ID를 알고 있다면 직접 지정해도 됩니다.

작업 ID는 대화 ID와 다릅니다. 같은 작업이면 기존 ID를 사용합니다. 기본 조회와 재개는 현재 상태를 짧게 보여주고, 과거 기록은 필요할 때 펼쳐 봅니다. 원장을 지우거나 요약본으로 바꾸는 방식은 아닙니다. 폴더를 수동 이동했다면 정확한 새 경로로 `attach_workspace`를 요청할 수 있습니다. 파일을 직접 수정하거나 이동한 경우 재개 검사에서 차이를 보여주며, 명시적으로 채택하기 전에는 기록을 바꾸지 않습니다.

확장된 작업공간의 `WORKSPACE.md`에서 목표·확정 결정·자료·최신 결과물·다음 행동을 확인할 수 있습니다. 안내서를 직접 수정했더라도 엔진이 조용히 덮어쓰지 않습니다. 기록과 파일이 다르면 에이전트가 차이를 확인해 정리해야 합니다.

## 자료가 바뀌었을 때와 같은 업무를 반복할 때

> CSV가 바뀌었어. 필요한 부분만 반영하고 이전 보고서는 보관해줘.

에이전트가 입력과 생성 단계를 연결해 둔 작업에서는 변경된 자료를 쓰는 단계와
그 이후 단계를 확인합니다. 변하지 않은 자료로 만든 결과는 조건을 확인해 재사용합니다.
생성 중인 결과와 마지막으로 검증한 최종본을 구분하므로, 중간에 작업이 끊겨도
불완전한 결과가 새 최종본으로 바뀌지 않습니다.

> 지난번 방식으로 이번 달 보고서를 만들어줘.

잘 끝낸 작업의 절차를 레시피로 저장했다면 새 자료와 기간을 연결해 새 작업을
시작할 수 있습니다. 같은 보고서의 수정은 기존 작업을 이어가고, 다른 달이나
고객을 위한 결과는 새 작업으로 관리합니다. 이전 작업의 검사 통과와 승인은
새 결과로 복제되지 않습니다.

단계 등록과 레시피 처리는 현재 에이전트가 맡습니다. 사용자가 명령이나 내부 ID를
외울 필요는 없습니다. 다만 과거 작업에서 기록하지 않은 관계를 엔진이 알아서
복원하지는 않습니다. 필요한 연결을 확인한 뒤 적용하며, 첫 버전의 부분 재생성은
명시한 파일·단계 단위입니다. 상세 계약과 실행 예제는 [작업과 레시피](WORKFLOWS.md)에 있습니다.

## 원본, 버전, 승인

- 자료는 지정한 원본을 참조하거나 복사합니다. 원본을 자동 이동·삭제하지 않습니다.
- 새 결과물은 `이름-v001`, `이름-v002`처럼 보존합니다. 생성 중인 파일은 임시 경로에 쓰고 저장 확인 후 등록합니다.
- 파일 해시 확인, 내용 검토, 사용자 승인, 외부 제출은 각각 다릅니다.
- 승인은 특정 버전·해시에 연결됩니다. 이후 새 버전은 자동으로 승인되지 않습니다.
- 완료한 작업을 다시 수정하려면 재개 의사와 사유를 명시합니다. 기존 완료 기록과 승인본은 보존됩니다.

기존 개발 프로젝트를 연결해도 소스 구조는 유지합니다. 작업공간에는 선택한 코드 변경과 검사 결과를 기록합니다. 원본 폴더는 설정의 `allowed_source_roots`에 명시적으로 허용된 곳만 사용할 수 있습니다. 새 프로젝트를 연결할 때 필요한 경로만 설정에 추가하고 연결을 다시 시작하세요. 홈 폴더 전체를 허용할 필요는 없습니다.

## 완료 판정과 지침 갱신

큰 작업을 시작할 때는 완료 증거, 기준의 출처, 사람이 판단할 부분을 구분해 주세요. 판정이 비어 있거나 `모름`이면 완료로 처리되지 않습니다. 독립 검토가 필요한 기준에는 실제 실행과 다른 검토 맥락의 참조를 남기며, 같은 참조를 독립 검토라고 기록할 수 없습니다. 파일 무결성과 내용 판단은 계속 구분합니다.

실패·모름·합격의 변경 이력은 보존됩니다. 같은 실패가 반복되면 수정안을 제안할 수 있지만, 검증하지 않은 제안을 새 규칙이나 성공 기록으로 자동 확정하지 않습니다. 사람이나 에이전트가 해결해야 할 사항은 `attention`에 남고 명시적으로 해소해야 완료할 수 있습니다.

설치된 스킬이 이전 관리 기본본 그대로이면 업데이트할 수 있습니다. 사용자가 고친 스킬은 보존하고 기존 기준본·현재본·새 후보의 차이를 보여줍니다. 설치 미리보기는 설정을 바꾸지 않습니다. 자세한 계약은 [지속가능성 설계](SUSTAINABILITY.md)에 있습니다.

## Codex와 함께 동작하는 방식

Codex가 실행 책임을 맡고 직접 작업하거나 내장 에이전트에 독립 작업을 나눕니다. Retulo는 파일·버전·현재 상태를 관리합니다. 하위 에이전트는 상위 담당자가 지정한 작업과 저장 경로를 사용하며 같은 과제의 작업공간을 다시 만들지 않습니다.

설치기는 기존 전역 지침을 보존하면서 관리 블록을 추가하고, 새 세션·사용자 요청·하위 에이전트 시작 훅만 추가합니다. 기존 종료·중단 훅, 모델·추론 설정, 허용된 자료 루트는 바꾸지 않습니다. 훅은 현재 작업 후보와 미완료 예약 등을 짧게 알려줄 뿐, 질문만으로 공간을 만들거나 중단된 작업을 다시 시작하지 않습니다.

새 훅은 Codex의 신뢰 검토가 필요합니다. 설치 완료 표시와 실제 훅 실행은 다르므로 새 연결에서 신뢰 상태와 동작을 확인합니다. 훅이 실행되지 않아도 전역 기본 지침은 남지만, 세션 문맥 전달까지 검증됐다고 보고하면 안 됩니다.

## 현재 검증 범위

이 후보는 macOS 로컬 환경의 격리 설치·복구와 실제 CLI/MCP 전송을 검증합니다. 이전 개발본의 실제 Codex 검증과 이번 후보의 검증 범위는 QUALIFICATION.md에 구분합니다. 다른 회사의 에이전트는 공통 CLI/MCP 계약으로 연결할 수 있는 구조이며, 실제 호환성 검증은 아직 하지 않았습니다. 엔진은 별도 모델, 백그라운드 감시, 새 채팅 생성, 외부 게시·결제를 실행하지 않습니다.

## 설치 되돌리기

설치 시 반환된 스냅샷을 보관하세요. `scripts/restore_codex.py`는 정확한 스냅샷과 대상 경로를 명시해 먼저 미리보기하고, `--apply`를 추가할 때만 설치 단계 하나를 되돌립니다. 설치 후 사용자가 바꾼 파일은 덮어쓰지 않고 충돌로 보고합니다. 여러 업데이트는 최신 단계부터 역순으로 되돌립니다. 작업 결과물은 삭제하지 않습니다. [복구 안내](RESTORE.md)를 참고하세요.
