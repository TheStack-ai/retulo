# Get help and contribute

English, 简体中文, and 한국어 are welcome. A small, concrete example is more useful
than a full task archive.

## Choose a starting point

| What you need | Where to start |
| --- | --- |
| Install Retulo or run the first example | [README](../README.md) and [FAQ](FAQ.md) |
| Understand a workflow, input binding, or recipe | [Workflows and recipes](WORKFLOWS.md) |
| Report behavior you can reproduce | **Issues → New issue → Bug report** |
| Propose support for a new task | **Issues → New issue → Feature request** |
| Ask a usage question or clarify a document | **Issues → New issue → Documentation or usage question** |
| Report a possible vulnerability | [Security reporting](../SECURITY.md), before sharing details |
| Submit a fix or example | [Contributing](../CONTRIBUTING.md) |

Open an [issue](https://github.com/TheStack-ai/retulo/issues/new/choose) for a bug or feature request.
Use [Discussions](https://github.com/TheStack-ai/retulo/discussions) for usage questions and shared examples;
the documentation issue form also remains available. English, Simplified Chinese
and Korean reports are welcome.

## Help someone reproduce the problem

Include the Retulo version, operating system and architecture, Python version,
and client or connection method. Explain what you tried, what you expected, and
what happened. For file operations, say whether the source material and earlier
outputs remain present.

Replace real content with a few invented files in a temporary folder. Include only
the relevant redacted error lines. Do not upload a workspace, conversation export,
credentials, private documents, or installer snapshots.

## Share an idea or a recipe

Start with the work you want to complete, the current workaround, and an example
of a successful result. For a recipe, describe the required inputs, tools, output
files, and checks. Include sample data that another person can run locally.

Keep discussion focused on the work and make room for questions from new users.
Maintainers may ask for a smaller reproduction or more evidence before deciding
on a change. If a proposal needs a design decision, discuss that decision before
opening a large pull request.

## Maintainer setup

Before opening the repository to contributors, follow [the publication checklist](PUBLICATION.md).
It describes labels, discussion routes, private reporting and release checks.
The public repository settings and hosted results must be checked separately from local tests.
