01 / 适用场景

适合一次对话做不完的工作。

当下一次修改需要上次的资料、决定和进度时，为工作留下清楚的起点。

反复修改方案

已有初稿和参考资料，又收到了一轮反馈。

集中保留受管理的输出版本和决策。新对话中指定同一任务，继续修改方案。

更新定期报告

报告完成后，又有了新的数据。

对已定义步骤的工作流，查看哪些部分需要重做。通过保存的工作流模板开始下一份报告，并重新检查结果。

并行开发代码

同一代码仓库中的两个功能需要各自的工作目录。

把每个任务连接到 Git worktree，保留选定文件，检查整合计划，再分别执行合并和受管理工作目录的清理。

连接的 Agent 执行工作，Retulo 管理任务记录。创建 Git 工作目录前，需要先配置允许的路径。

02 / 随任务保留的内容

为下一步留下起点。

最终文件只是工作的一部分。把输入资料、旧版本、决策与待办事项放在一起，方便 Agent 继续工作。

01

从日常请求开始

完成配置与信任后，已连接的 Agent 可在处理日常请求时遵循同一文件工作流程。纯问答和规划不会创建工作区。

02

继续同一个任务

稳定的任务 ID 与工作区将不同会话中的工作连接起来。继续时，请提供任务 ID、工作区路径或实际产物引用。

03

管理原始资料与历史版本

预留输出位置、登记已保存的文件，并保留受管理的历史输出。现有代码仓库保持原有位置。

04

了解任务进展

精炼的当前指引中包含决策、剩余工作、检查与审批记录。文件已保存、内容已检查与用户已批准分别记录。

运行文件任务续接示例
.venv/bin/python scripts/demo_continuity.py --output-dir /tmp/retulo-continuity-demo

可选的源码示例：先完成安装指南中的开发设置，使用新的空输出目录。独立 CLI 进程在同一任务中生成并修改指南，保留旧版本。它检查 CLI 续做，不检查新 Agent 会话是否采用流程。

04 / 从一个任务开始

安装软件包，连接你的项目。

安装 Retulo，连接 Codex 或 Claude Code，再选一份需要修改的文档试用。你仍向原来的 Agent 提出请求，Retulo 提供管理工作区的工具。

安装 Retulo

curl -fsSL https://thestack-ai.github.io/retulo/install.sh | sh
retulo --version

应显示 retulo 0.6.0rc1。若找不到命令，请运行安装程序显示的 PATH 命令（默认：export PATH="$HOME/.local/bin:$PATH"）。不会修改 shell 配置文件。本预览版通过 GitHub Releases 分发。

连接 Codex 或 Claude Code

retulo setup codex --project /absolute/path/to/project
retulo setup codex --project /absolute/path/to/project --apply
retulo doctor codex --project /absolute/path/to/project --connect

将项目路径替换为已有目录。第一条命令预览，--apply 才写入配置。Claude Code 将三条命令中的 codex 换成 claude。重启客户端，按提示信任项目或钩子并批准 MCP 服务。doctor --connect 检查本地 MCP，不调用模型。

然后提出日常工作请求

根据这些笔记写一份方案初稿。保留原始资料，并作为 Retulo 任务管理。

在新会话中，请同时提供现有工作区或文件引用

继续 Retulo 工作区 /absolute/path/to/workspace 中的方案。调整时间表，并保留上一版。

05 / 重复和改进

输入发生变动，
有效成果依然保留。

对于已声明的工作流，Retulo 连接输入、生成步骤与具体输出。输入变化后，Agent 可以判断哪些步骤需要重新处理。

05

重建受影响的步骤

宿主 Agent 重新运行所需工具，保留此前的最终文件。未声明的依赖关系不会被自动发现。

06

复用工作流模板

用带版本的输入与参数创建新任务。新任务重新检查，不继承已有审批或检查结论。

运行完整的本地示例
.venv/bin/python scripts/demo_incremental.py --output-dir /tmp/retulo-report-demo

可选的源码示例：先完成安装指南中的开发设置，再从源码目录运行，并使用新的空输出目录。它生成 HTML 报告、更新受影响步骤、保留旧报告并创建新的模板任务。不调用模型或修改全局设置。

先了解这几个区别。

Retulo 会记住所有对话吗？

Retulo 记录受管理的任务、文件与进度。跨会话继续时，请指定同一任务或工作区。核心不会重建未接收的对话。

Retulo 会编写或评估内容吗？

当前 Agent 理解请求并运行工具。Retulo 管理工作区，记录文件完整性、检查与审批。检查记录本身不保证内容质量。

目前支持哪些环境？

已完成 macOS 本地验证，以及 macOS、Ubuntu 上 Python 3.11 和 3.14 的 CI 检查。Windows、网络存储、多主机和其他客户端需要单独验证。协议检查不代表某次对话一定遵循工作流程。

需要安装和连接哪些内容？

运行软件包安装程序，再针对已有项目使用 retulo setup codex 或 retulo setup claude。设置命令创建本地配置和受管客户端指令。请另外安装并登录 Codex 或 Claude Code；Retulo 不提供模型账户或后台服务。
