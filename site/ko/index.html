01 / 기본 작업 관리

작업에 필요한 것을 한곳에.

작업은 마지막 결과물 파일 하나로 끝나지 않습니다. Retulo는 연결된 에이전트가 참조할 수 있도록 원본 자료, 버전 내역, 결정 사항과 검증 기록을 체계적으로 보관합니다.

01

평소처럼 요청하기

연동을 설정하고 신뢰하면, 연결된 에이전트가 일반 요청에도 같은 파일 작업 절차를 적용할 수 있습니다. 질문과 계획만으로는 작업공간을 만들지 않습니다.

02

같은 작업 이어가기

고정된 작업 ID와 작업공간으로 대화가 바뀌어도 작업을 연결합니다. 이어갈 때 작업 ID, 작업공간 경로 또는 실제 결과물 참조를 제공합니다.

03

원본과 이전 결과 관리

저장할 경로를 정하고 실제 파일을 등록하며 관리 대상의 이전 결과를 보존합니다. 기존 코드 저장소는 원래 위치에서 작업합니다.

04

현재 상태 파악하기

짧은 현재 안내에 결정 사항, 남은 일, 검증과 승인 기록을 남깁니다. 파일 저장, 내용 확인, 사용자 승인을 구분합니다.

파일 작업 이어 하기 예제 실행

.venv/bin/python scripts/demo_continuity.py --output-dir /tmp/retulo-continuity-demo

선택적인 소스 예제입니다. 상세 설치 안내의 개발 환경을 먼저 준비하고 새로운 빈 출력 폴더를 사용하세요. 별도 CLI 프로세스가 같은 작업으로 안내문을 만들고 수정하며 이전 버전을 보존합니다. 새 에이전트 대화의 연동 채택까지 검사하지는 않습니다.

02 / 작동 방식

에이전트가 도구를 실행하고,
Retulo가 작업을 관리합니다.

01

할 일 설명

현재 에이전트가 요청을 해석하고 목표와 완료 기준을 구체화합니다.

02

작업 연결

파일을 만들기 전에 에이전트가 작업공간을 시작하거나 기존 작업을 식별합니다.

03

저장하고 확인

Retulo가 버전과 파일 무결성을 기록합니다. 에이전트나 사용자가 내용을 평가하고 결과를 남깁니다.

04

현재 상태로 이어가기

짧은 현재 안내를 읽고, 다음 단계에 필요하면 상세 기록을 확인합니다.

코어는 로컬에서 동작합니다. 모델이나 에이전트를 시작하거나 레시피 명령을 실행하지 않으며 폴더 감시와 결과 공개도 하지 않습니다.

03 / 빠른 시작

패키지를 설치하고 프로젝트를 연결하세요.

macOS 또는 Linux 터미널에서 설치기를 실행하세요. 릴리스 wheel을 검증하고 지속되는 실행 환경을 설치하며, 필요하면 uv와 Python도 준비합니다. 소스 폴더나 수동 가상환경은 필요하지 않습니다.

Retulo 설치

curl -fsSL https://thestack-ai.github.io/retulo/install.sh | sh
retulo --version

retulo 0.6.0rc1이 나오면 됩니다. 명령을 찾지 못하면 설치기가 표시한 PATH 명령을 실행하세요. 기본값은 export PATH="$HOME/.local/bin:$PATH"이며 셸 프로필은 수정하지 않습니다. GitHub 릴리스로 배포합니다.

Codex 또는 Claude Code 연결

retulo setup codex --project /absolute/path/to/project
retulo setup codex --project /absolute/path/to/project --apply
retulo doctor codex --project /absolute/path/to/project --connect

프로젝트 경로를 이미 있는 폴더로 바꾸세요. 첫 명령은 미리보기, --apply는 적용입니다. Claude Code는 세 명령의 codex를 claude로 바꾸세요. 클라이언트를 다시 열고 안내에 따라 프로젝트·훅을 신뢰하고 MCP를 승인하세요. doctor --connect는 모델 호출 없이 로컬 MCP를 검사합니다.

그다음 평소처럼 작업 요청

방문객 안내문을 Markdown 파일로 만들어줘. 원본 자료는 보존해줘.

새 대화에서는 기존 작업공간이나 파일 참조를 함께 제공

같은 작업공간에서 이 안내문을 이어서 수정해줘. 연락처를 추가하고 이전 버전도 남겨줘.
설치·진단·연결 해제 안내 읽기 ↗

04 / 갱신과 반복

자료가 바뀌어도,
쓸 수 있는 작업은 그대로.

단계가 명시된 작업에서는 Retulo가 입력 자료, 제작 단계, 정확한 결과물을 연결합니다. 입력이 바뀌면 에이전트가 어느 단계에 작업이 필요한지 확인합니다.

05

영향받은 단계 갱신

현재 에이전트가 필요한 도구를 다시 실행하고 이전 최종본은 보존합니다. 명시되지 않은 의존 관계까지 자동으로 알아내지는 않습니다.

06

작업 레시피 재사용

버전이 정해진 입력과 매개변수로 새 작업을 만듭니다. 검증은 새로 진행하며 기존 승인이나 통과 판정을 복사하지 않습니다.

완전한 로컬 예제 실행

.venv/bin/python scripts/demo_incremental.py --output-dir /tmp/retulo-report-demo

선택적인 소스 예제입니다. 상세 설치 안내의 개발 환경을 준비한 뒤 소스 폴더에서 새로운 빈 출력 폴더를 지정해 실행하세요. HTML 보고서 생성, 영향받은 단계 갱신, 이전 결과 보존과 새 레시피 작업을 확인합니다. 모델 호출이나 전역 설정 변경은 없습니다.

이 차이를 알아두세요.

모든 대화를 자동으로 기억하나요?

Retulo는 관리하는 작업, 파일과 진행 상황을 기록합니다. 다른 대화에서 이어갈 때 같은 작업이나 작업공간을 지정합니다. 코어가 전달받지 않은 대화를 복원하지는 않습니다.

내용을 쓰거나 평가하는 것도 Retulo인가요?

현재 에이전트가 요청을 해석하고 도구를 실행합니다. Retulo는 작업공간을 관리하고 파일 무결성, 검증과 승인을 기록합니다. 검증 기록만으로 내용의 품질이 보장되는 것은 아닙니다.

현재 확인된 환경은 무엇인가요?

로컬 검증 환경은 macOS와 로컬 파일 시스템입니다. 설치기는 macOS·Linux용이며 필요하면 Python 3.11 이상을 준비합니다. Linux 설치는 CI 검증 대상이고 Windows 수동 설치·네트워크 저장소·여러 호스트·다른 클라이언트는 별도 검증이 필요합니다.

무엇을 설치하고 연결해야 하나요?

패키지 설치기를 실행한 뒤 기존 프로젝트를 지정해 retulo setup codex 또는 retulo setup claude를 사용하세요. 로컬 설정과 관리 지침을 함께 만듭니다. Codex 또는 Claude Code의 설치·로그인은 별도로 하며, Retulo가 모델 계정이나 백그라운드 서비스를 추가하지는 않습니다.

06 / 도움과 기여

다음 작업이 더 쉬워지도록.

먼저 안내를 확인하고, 버그는 작은 재현 예제로, 새 기능은 그 기능으로 끝내고 싶은 작업과 함께 설명해 주세요.

GitHub wheel로 배포하는 프리뷰 버전입니다. macOS는 로컬에서 검증했고 Linux 설치는 CI 검증 대상입니다. 실제 검사와 현재 한계는 검증 기록에서 확인하세요.
